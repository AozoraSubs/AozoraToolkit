# 架构决策记录（初版）

## ADR-001：使用 Tauri 2 + Svelte 5 + TypeScript + Rust

- 状态：Accepted for MVP
- 背景：项目需要现代桌面 UI、轻量应用外壳和可靠的本地子进程管理。
- 决策：前端负责展示和用户交互；Rust 负责任务、配置和进程；FFmpeg/FFprobe 负责媒体处理。
- 原因：减少自研媒体处理工作，保持 UI 与进程管理边界清晰。
- 后果：开发环境包含前端与 Rust 两套工具链；应避免引入不必要的状态管理和插件。

## ADR-002：FFmpeg 作为外部媒体引擎

- 状态：Accepted for MVP
- 决策：通过参数数组启动 FFmpeg/FFprobe，而不是把媒体处理逻辑嵌入 GUI。
- 后果：需要检测工具版本、编码器能力和路径；打包时必须审查第三方许可证。

## ADR-003：先使用 JSON 保存预设和少量历史

- 状态：Accepted for MVP
- 决策：配置采用版本化 JSON。任务历史初期可用 JSON；当查询和数据规模需要时再评估 SQLite。
- 后果：必须设计 schema 版本与迁移；避免在多个文件中重复存储同一状态。

## ADR-004：不强制要求 Git commit 签名

- 状态：Accepted
- 决策：本项目不强制要求使用 OpenPGP 或其他形式的 Git commit 签名。
- 原因：项目开发流程不需要额外的硬件密钥签名门槛。
- 后果：开发者仍应审查提交内容并保持提交历史清晰；个人本机签名配置不受影响。


## ADR-005：使用 pnpm 作为唯一前端包管理器

- 状态：Accepted
- 决策：前端依赖统一由 pnpm 管理；`package.json` 固定 pnpm 版本，提交 `pnpm-lock.yaml`。
- 原因：避免多个包管理器造成依赖解析和锁文件不一致。
- 后果：本地开发与 CI 使用 pnpm；Rust 依赖仍由 Cargo 管理。


## ADR-006：使用 PLAN.md 跟踪实施进度

- 状态：Accepted
- 决策：以根目录 `PLAN.md` 作为实施任务与完成状态的唯一跟踪清单；AI 开发前必须阅读，完成并验证后更新复选框。
- 原因：避免计划与实际实现脱节，让开发过程可追踪、可交接。
- 后果：未验证的任务必须保持未勾选；计划变化需同步更新该文件。
